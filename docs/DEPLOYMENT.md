# Deployment

## Local Development Setup

Install dependencies:

```bash
npm install
```

Start development server:

```bash
npm run dev
```

Open the URL printed by Next.js. The default is:

```text
http://localhost:3000
```

If that port is busy, Next.js will use another port.

## Production Build

Run:

```bash
npm run lint
npm run build
```

Start the production server locally:

```bash
npm run start
```

`npm run start` requires a successful `.next` build.

## CI

GitHub Actions workflow:

```text
.github/workflows/build-web.yml
```

It runs:

```bash
npm ci
npm run lint
npm run build
```

The workflow uses Node.js 20.

## Vercel Deployment

This is a standard Next.js App Router project and can be deployed to Vercel without custom server code.

Recommended Vercel settings:

| Setting | Value |
| --- | --- |
| Framework preset | Next.js |
| Install command | `npm ci` |
| Build command | `npm run build` |
| Output directory | default `.next` |
| Node version | 20.x |

No environment variables are currently required.

## Next.js Configuration

Current `next.config.ts`:

```ts
const nextConfig = {
  trailingSlash: true,
};

export default nextConfig;
```

The app currently uses standard Next.js output, not static export.

## Static Export Considerations

Static export is not currently enabled.

If static export is required for CDN-only or Electron/offline packaging, evaluate:

```ts
const nextConfig = {
  trailingSlash: true,
  output: "export",
};
```

Before enabling it, verify:

- all workflow routes are generated by `generateStaticParams`
- compatibility screensaver redirects still behave as expected
- local video/image paths resolve correctly
- client-side language persistence still works
- direct deep links work from the exported folder

The current screensaver compatibility routes use `redirect()` from `next/navigation`; static export may require replacing these with static/client-side redirect pages or host-level redirects.

## Environment Variables

None at the moment.

There is no API key, CMS endpoint, external asset host, or backend service required by the current implementation.

## Asset Handling

Assets are local-only under:

```text
public/assets
```

They are served by Next.js as public static files:

```text
/assets/workwear/...
/assets/mantel/...
/assets/key-visual/...
/assets/nachtwaesche/...
```

Deployment platforms must preserve the `public` folder.

Large videos increase deployment size and first-load bandwidth. Keep videos compressed and test on the target presentation network.

## Browser Compatibility

The app targets modern desktop browsers.

Recommended:

- current Chrome
- current Edge
- current Safari

Important browser features used:

- CSS `dvh`
- CSS transforms
- video autoplay with muted inline video
- pointer events
- `localStorage`

Below `900px`, the app intentionally shows the desktop-required guard.

## Web vs Kiosk Behavior

Current web behavior:

- no forced fullscreen
- no reload blocking
- no right-click blocking
- no Electron APIs
- no inactivity redirect
- no global kiosk shortcuts
- normal browser navigation and deep links

Kiosk-inspired behavior retained:

- immersive no-scroll screens
- touch-friendly controls
- local assets
- fixed demo compositions
- full-bleed cover/intro/final media

## Performance Considerations

- Keep image dimensions appropriate for desktop display.
- Use compressed MP4 for videos.
- Avoid replacing PNG/JPG files with uncompressed production exports.
- Avoid adding remote assets unless there is a clear deployment reason.
- Test workflow cover videos on the actual display hardware.
- Use browser dev tools to check video decode and memory if adding longer videos.

## Deployment Checklist

Before handoff or production deploy:

```bash
npm ci
npm run lint
npm run build
```

Manual smoke test:

- `/`
- `/admin`
- `/workflow/workwear`
- `/workflow/mantel`
- `/workflow/key-visual`
- `/workflow/nachtwaesche`
- one representative step in each workflow
- each final screen
- viewport below `900px`

Confirm:

- no desktop scroll
- local assets load
- videos autoplay muted
- language selection persists
- full-bleed screens reach viewport edges
- CTA buttons are visible
